# Deep Learning-Based Image Captioning

**A Comparative Analysis of CNN-LSTM, Attention, Transformer and Pretrained Models**

This project generates an English sentence that describes a photo. Four models are compared on Flickr8k (8091 images, 5 captions per image): a Show-and-Tell style CNN-LSTM (Model 1), an LSTM with Bahdanau attention (Model 2), a Transformer decoder (Model 3) and pretrained BLIP (Model 4; without and with fine-tuning). Models 1–3 share the same split, the same vocabulary and the same frozen ResNet50 feature cache. The comparison covers accuracy (BLEU, METEOR, ROUGE-L, CIDEr), caption diversity, computational cost and interpretability (attention maps).

## Reproducing the results

This section lists, in order, how every number under `results/` was produced. Run the commands from the repository root. Loops use bash syntax (Linux/macOS or Git Bash); in PowerShell run the commands one by one.

**Overwrite rules.** `src.train` and `src.predict` (in the default folder) overwrite the committed files under `results/<name>/`; check the difference with `git diff --stat results/` and revert with `git checkout -- results/`. `src.evaluate --output` and `src.predict --output-dir` **never** overwrite an existing file: to re-score in place, delete the old `val_metrics_*.json` first or give a different path.

**Timings.** Training times are the `train_minutes` field in `results/<name>/summary.json` (CUDA, AMP); the Model 1 run was on an RTX 3050, and times differ on other GPUs. Prediction times are `ms_per_image` in `val_metrics.json` × 1000 images (decoding only; model and cache loading excluded).

## Fixed decisions

The following decisions were fixed for the whole project; all models and experiments follow them.

- **Shared data:** Models 1–3 use the same split, the same vocabulary and the same ResNet50 cache. BLIP uses its own image processor and tokenizer.
- **Split:** image-based, train 6000 / val 1000 / test 1000; produced once, never changed.
- **Text:** lowercased, punctuation removed. Vocabulary built from training captions only, minimum word frequency 5. Tokens `<pad>`, `<start>`, `<end>`, `<unk>`.
- **Length:** at most 34 tokens, including `<start>` and `<end>`. Padding on the right. Generation starts with `<start>` and stops at `<end>` or at 34 tokens.
- **Images (Models 1–3):** short side 256, 224×224 center crop, ImageNet normalisation; frozen ResNet50 (`IMAGENET1K_V1`) layer4 output, 2048×7×7.
- **Seed:** 42.
- **Training:** teacher forcing, cross-entropy ignoring padding, gradient clipping 5, AMP. Early stopping on validation loss (patience 5); `best.pt` selected by greedy validation CIDEr.
- **Metrics:** computed on plain sentences; `<start>`, `<end>`, `<pad>` and `<unk>` removed, predictions and references lowercased, punctuation removed. The main table has greedy and beam-3 for every model; nucleus is a separate diversity experiment.
- **Interface:** every model exposes `generate(image) -> caption`. Training reads from the cache, the demo takes raw images (`app/captioners.py`, `src/models/attention_captioner.py`).
- **The test set** is used once, only for the final table.
- **Experiments:** each experiment changes a single setting, recorded in its experiment config.
- Data, feature cache, checkpoints and `kaggle.json` are never committed.

## Details

### Data pipeline

- Split: `src/data/artifacts/flickr8k_split.json`. Train 6000, val 1000, test 1000; 91 images are in `unused` and never used for training.
- Vocabulary: `src/data/artifacts/vocab.json`, 2572 tokens (2568 words + 4 special tokens). Words with frequency below 5 become `<unk>`.
- Paths are in `configs/base.yaml`. Local data: `data/flickr8k/Images` and `data/flickr8k/captions.txt`.
- `token_ids` has length 34: `<start>`, words, `<end>`, `<pad>` on the right. Training reads through `build_dataloader(split)`. The cache is keyed by `image_id` (file name).
- Data statistics: `results/eda/summary.json`, `results/eda/sentence_lengths.png`, `results/eda/word_frequencies.png`.

#### Data preparation script

```bash
python -m src.data.prepare
```

The split file, vocabulary and the files under `results/eda/` were produced by this script. In normal use **you do not need to run it**. The script takes no command-line options; it runs even if `--help` is passed.

- The script **overwrites** `flickr8k_split.json` and `vocab.json`. Because seed 42 is fixed, the same data gives the same result. If `git status` shows changes in these two files after running it, your data is different: do not commit the change, revert it with `git checkout -- src/data/artifacts`.
- What it does: matches images and captions, tests text cleaning, builds the split and vocabulary, writes the EDA plots and `results/eda/summary.json`, and checks a sample batch for train and val (shape, `<start>`, right padding, leakage between splits).

### Feature cache

Models 1–3 read the frozen ResNet50 layer4 output instead of images. The transform and encoder are in `src/data/features.py`; the demo uses the same module through `extract_image`.

- Outputs are in `data/features/`: `resnet50_layer4.npy` (fp16, `[8091, 2048, 7, 7]`, about 1.6 GB), `resnet50_layer4_index.json` (`image_id -> row`) and `resnet50_layer4.meta.json` (weights, dtype, shape, versions). The paths are the `features_path` and `features_index_path` fields in `configs/base.yaml`.
- Options: `--images-dir`, `--out-dir`, `--batch-size`, `--limit` (first N images, for testing), `--device`, `--num-workers`, `--no-amp`. Autocast is used on GPU; the cache is always saved as fp16.
- On Kaggle the input is read-only, so write the output to the working folder:

```bash
python -m src.data.cache_features --images-dir /kaggle/input/flickr8k/Images --out-dir /kaggle/working/features
```

- Training: `build_dataloader("train", use_features=True)` adds `features` (float32, `[B, 2048, 7, 7]`) to each batch. If the cache is in another folder, pass `--features-dir` to `src.train` / `src.predict`.
- Validation: `build_eval_dataloader("val")` gives one sample per image (`image_id`, `features`). `load_references("val")` returns the 5 cleaned captions of each image. Both open the test set only with `allow_test=True`.

### Training

```bash
python -m src.train --config configs/model1.yaml
```

- Models 1, 2 and 3 are trained with the same script; each model's settings are in its own file under `configs/`, shared settings in `configs/base.yaml`.
- Reads from the cache; teacher forcing, cross-entropy ignoring padding, gradient clipping 5, AMP (on GPU), seed 42.
- Validation loss is computed every epoch. Greedy CIDEr is computed every `cider_every` epochs, when the loss improves, and at the last epoch. Early stopping uses `early_stopping.monitor` (default `val_loss`, patience 5); `best.pt` is selected by `evaluation.select_by` (default `val_cider`).
- Outputs: `checkpoints/<name>/best.pt` and `last.pt` (not committed), `results/<name>/history.json`, `loss_curve.png`, `summary.json`, `val_captions_best.json`.
- Options: `--name`, `--max-epochs`, `--limit-batches` (for testing), `--features-dir` (Kaggle), `--num-workers`, `--device`, `--resume` (continue from `last.pt`).
- The data-amount experiment uses `data.train_fraction` in the config (e.g. `0.25`); the subset is image-based and fixed by the seed. GloVe initialisation is enabled by the top-level `embeddings` section of the config (`src/data/glove.py`).
- Validation CIDEr during training is computed with batched greedy decoding (same rules as `src/decode.py`); the final table is produced with `src.predict` and `src.evaluate`.
- New models are added to the `MODELS` dictionary in `src/train.py`. Interface: `forward(features, caption_inputs) -> (logits, attention or None)`.

### Experiments

Each experiment changes a single setting relative to the reference config.

| Experiment | Config | Changed setting |
|---|---|---|
| Data amount | `configs/model1_frac25.yaml`, `configs/model1_frac50.yaml` | `data.train_fraction` (relative to `configs/model1.yaml`) |
| Embedding (control) | `configs/model1_emb300.yaml` | `model.embedding_dim: 300`, random initialisation |
| Embedding (GloVe) | `configs/model1_glove300.yaml` | `emb300` + GloVe initialisation (`embeddings` section, `freeze: false`) |
| Decoding method | — (same checkpoint) | greedy / beam-3 / nucleus p=0.9 |
| With / without attention | `configs/model1.yaml` → `configs/model2.yaml` | visual attention in the decoder |

The GloVe comparison is between `emb300` and `glove300`; the 256-dimensional `model1_lstm` is only a reference.

### Caption generation

```bash
python -m src.predict --checkpoint checkpoints/model1_lstm/best.pt --method greedy
python -m src.predict --checkpoint checkpoints/model1_lstm/best.pt --method beam --beam-size 3
```

- Options: `--method {greedy,beam,nucleus}`, `--beam-size`, `--top-p`, `--seed`, `--limit`, `--features-dir`, `--output-dir` (separate folder; never overwrites existing files), `--device`, `--split`, `--allow-test`.

### Evaluation

```bash
python -m src.evaluate --predictions results/model1_lstm/val_captions_greedy.json --model-name model1_lstm --meteor --output results/model1_lstm/val_metrics_greedy.json
python -m src.evaluate --predictions results/model1_lstm/val_captions_beam3.json --model-name model1_lstm --method beam --beam-size 3 --meteor --output results/model1_lstm/val_metrics_beam3.json
```

- Metrics: BLEU-1..4, METEOR, ROUGE-L, CIDEr (pycocoevalcap 1.2, raw scale). References are read from `data/flickr8k/captions.txt` (or from a JSON file with `--references`).
- `--meteor` needs Java; without Java, run without this option.
- **Turkish locale issue:** when Java runs with a Turkish locale, the METEOR jar cannot parse decimal numbers and `evaluate.py` reports "METEOR failed or timed out" (it is not a timeout; it fails within seconds). The fix, without changing the installation, is to run the command with `JAVA_TOOL_OPTIONS="-Duser.language=en -Duser.country=US"` (PowerShell: `$env:JAVA_TOOL_OPTIONS = "-Duser.language=en -Duser.country=US"`). This setting does not change BLEU, ROUGE-L or CIDEr.
- `--output` never overwrites an existing file.

## Limitations and notes

- **Single seed:** every training run was done once with seed 42. The tables contain no variance or confidence intervals; small differences (e.g. +0.008 CIDEr for GloVe with beam-3) may be within noise. Only the nucleus experiment was repeated with three seeds, and that repetition changes only the sampling, not the training.
- **Determinism:** training runs on GPU with AMP and cuDNN is not put in deterministic mode; the same commands may not give exactly the same numbers on other hardware (or even on the same hardware).
- **The test set was opened once:** test results of all four models (BLIP with both variants) are under `results/<name>/test/`. For every model the checkpoint was selected by greedy CIDEr on the validation set. The fine-tuned BLIP was trained on Kaggle (`transformers 4.57.1`) and its test inference was run locally (`transformers 5.17.0`); on 100 validation images, greedy captions matched 100/100 and beam-3 captions 96/100.
- **Not zero-shot:** the "not fine-tuned" BLIP was already trained for captioning on COCO; it has only not seen Flickr8k.
- **GloVe Kaggle copy:** the official Stanford server was unreachable, so a copy on Kaggle was used. The copy was checked by file size, line count, first line and simple analogy / neighbour tests (`results/model1_glove.md`); the official file was not downloaded and compared directly.
- **METEOR depends on Java:** without Java, METEOR is not computed; with a Turkish locale the environment variable above is required.
- **Pinned package versions:** the tested versions are pinned in [requirements.txt](requirements.txt) for Python 3.12.3 ([report/demo_dogrulama.md](report/demo_dogrulama.md)); different hardware or CUDA versions may still cause small numerical differences.
- **Model 2 checkpoint is not in the repository:** Model 2 results can be read from the committed JSON files; for re-scoring and the demo, get the checkpoint from the team or retrain.
- **General limitations:** the models can describe objects that are not in the image (hallucination), biases in the training data carry over into the captions, and small data leads to generic sentences. Qualitative comparison and the 40-image error review: [report/kalitatif_karsilastirma_4model.md](report/kalitatif_karsilastirma_4model.md).
- **Example images:** the photos shown in the attention figures under `results/` come from the Flickr8k dataset (Hodosh et al., 2013). The photos belong to their owners on Flickr and are shown here only as examples for research and education.
- **Checkpoint loading:** all checkpoints are opened with `torch.load(..., weights_only=True)`; a file can only contain tensors and basic data types and cannot run code.
